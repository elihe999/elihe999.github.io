My Travel Journal: Tokyo Trip

东京奇妙日：在传统与现代之间穿行 清晨五点半，浅草寺的钟声还未敲响，我已经站在雷门前的石板路上。晨光像薄薄的金箔，轻轻贴在仲见世商店街的屋檐上。此时的东京不属于游客，而属于那些刚结束夜班、骑着自行车穿过巷口的普通人。我买了一只热腾腾的鲷鱼烧，糖馅烫嘴，却让人瞬间清醒——这是旅程的第一口温度，也是这座城市给我的第一个拥抱。 随后，我钻进日比谷线的车厢。银座的地下并不喧嚣，只有皮鞋敲击地面的声音像鼓点，催促着某种看不见的秩序。但只消拐进一条小巷，世界立刻换了底色：筑地市场的余韵仍在，几家不起眼的寿司店门口挂着“本日休业”的手写木牌，隔壁却传来玉子烧在铁板上滋啦作响的声音。我走进一家只有六张吧台的小店，老板一言不发，却用海苔包裹住刚出锅的蛋卷递给我。那一刻我忽然明白：东京的高级，从不写在招牌上，而藏在“不必多言”的细节里。 午后，我登上六本木之丘。从观景台俯瞰，整座城市像一块巨大的集成电路板，楼群是元件，道路是走线，车流是电流。远处，东京塔在阳光下泛着暖红，晴空塔则冷静地刺向云层。一边是昭和时代的浪漫，一边是令和的锋利，它们互不干扰，却又在同一幅天际线下共生。这种新旧并置的从容，大概就是东京最迷人的地方——它从不急着否定过去，也不畏惧奔向未来。 黄昏时分，我迷失在下北泽的唱片行与古着店之间。这里没有银座的光鲜，却有无数年轻人背着吉他、抱着黑胶，眼神里有种不肯被规训的光。我在一家咖啡馆坐下，窗外电车驶过，窗帘轻轻扬起。咖啡是手冲的，酸质明亮得像少年心事。邻桌的老人正用老式胶片机拍照，咔嚓一声，仿佛把时间也一并定格。 夜深，我走在隅田川畔。对岸的灯光倒映在水面，碎成一片流动的银河。河风微凉，却吹不散这座城市的体温。我想起这一天的种种：寺庙的沉香、地铁的人潮、寿司的鲜甜、楼顶的风、陌生人的微笑。东京从不是单一的表情，它是一首复调的歌——传统是它的低音，现代是它的高音，而生活，是其中永不间断的节拍。 旅程终会结束，但有些东西留了下来：一种相信秩序与自由可以共存的信念，一种在喧嚣中依然寻找安静的能力。东京没有教会我如何逃离日常，却悄悄告诉我——只要脚步足够真诚，每一天都可以是一场小型的奇迹。

让AI先对齐再动手-SDD科普

我的 SDD 笔记整理：规格、门禁，以及凭什么说做完了 翻了一遍仓库里跟规范驱动开发有关的笔记：Spec/ 六篇、模板/ 里三个版本的 ADR、AI开发流程/ 的测试与 OpenAPI，加上散在 AI/ 里的上下文和多代理记录。它们记的时间点不同、粒度也不同，但串起来读，其实只在回答三个问题。 一、规格真正值钱的是两个字段 [[基本流程]] 里列了 spec 该有的六项：Problem Statement、Success Metrics、User Stories、Acceptance Criteria、Constraints，外加 Goals / Non-Goals。同一篇里还有一段登录功能的例子，需求写成 SHALL rate-limit to 5 attempts per 15 minutes，场景写到"第 6 次失败 → 提示限流"，约束写到"不得暴露邮箱是否存在"。 这些字段我一开始当成格式要求，后来发现真正起作用的是其中两个。Non-goals 挡的是 AI 的静默假设和过度工程——超出范围的猜想不再由它自行决定；可观察的验收标准挡的是"应该没问题了"。[[constitution]] 的四条原则里就有一句"验收标准必须可观察"，而 [[基本流程]] 在 Success Metrics 后面直接标了"必须可量化"。写不出可验证条款的时候，通常不是模型的问题，是我自己没想清楚。 顺带一提，[[基本流程]] 的 Feature Spec 模板还留了一格边界条件矩阵：空值缺省、重复幂等、并发竞态、权限可见性。这四格是我漏得最多的地方。 二、一次变更不是一个文件，是五件套 [[基本流程]] 里那个 docs/specs/checkout-coupon/ 目录我抄下来了：proposal.md（为什么现在做、影响谁）、spec.md（需求和场景）、design.md（决策和取舍）、tasks.md（可评审的实现切片）、test-evidence.md（合并前必须提供的证据）。 入口是 [[Spec/spec|spec.md]] 那份提案模板，带 Draft / Review / Approved 状态机；末尾有一栏 Evidence Required——测试、日志或指标、手工核对、回滚信号，四种证据在开工前就得声明，不是事后补。 不同工种的规格另有模板：[[db-spec-template]] 要求写迁移步骤、回填策略、回滚方案，还有一栏读写兼容窗口；API 模板要求写向后兼容说明和废弃策略。取舍记录用 ADR，[[ADR|模板目录]] 里存了三种版本：最简的 Nygard（状态 / 背景 / 决定 / 后果）、MADR 完整版（多了决策者、驱动因素、候选方案）、以及我自己那份五行版。MADR 里有条提示值得记住：候选方案不要遗漏最终被否决的选项——被排除的路径正是后人不重复踩坑的原因。 ...

与神对话的时代，我选择失语

我已经记不清，上一次为了一个指针越界而彻夜未眠，是在哪一年的雨季。 那时候的代码是有脾气的。每一行代码都像是精心修剪的盆景，每一个 Segmentation Fault 都是一场小型的地震。我会盯着屏幕，像解读罗塞塔石碑一样去揣摩编译器的心思，手指在机械键盘上敲击出某种近乎仪式的节奏。那时的痛苦很具体，快乐也很具体——当程序终于跑通，绿灯亮起的那一刻，那种创造者的孤傲，足以支撑我度过整个潮湿的夏天。 现在不一样了。 现在我只需要动动嘴。我说，“帮我写一个分布式锁，要考虑红锁算法和时钟跳跃的问题。” 几乎是瞬间，整齐划一、注释详尽、甚至附带单元测试用例的代码块就流淌了出来。它太完美了，完美得像是从教科书里撕下来的范本，没有一丝烟火气，也没有一丝属于人类的笨拙。 AI 实在太好用了。好用到让人感到一种彻骨的寒意。 我就像一个拥有了阿拉丁神灯的人，不用再挥汗如雨地挖掘宝藏，只需要擦拭神灯，看着愿望自动实现。软件开发的逻辑被彻底颠覆了：从"构建"变成了"描述"，从"工匠"变成了"监工"。 但我失去了什么？ 我失去了那种在迷雾中摸索，最后亲手触碰到真理边界的战栗。那些曾经让我抓耳挠腮的算法细节，如今只是黑盒里吐出的标准答案。我的手指不再因为思考而颤抖，它们只是负责复制和粘贴。我的脑子不再因为优化而沸腾，它只是负责判断这段代码"看起来对不对"。 我开始怀念那些"无用"的时刻。 在这个效率至上的时代，我们消灭了 Bug，也顺带消灭了程序员这个职业里最珍贵的"手感"。我们不再需要理解底层逻辑的泥泞，我们只需要结果。这不仅仅是工具的革新，这是人类在技术面前的一次集体退位。 今晚，窗外下着和那年一样的雨。我看着屏幕上由 AI 生成的、优雅得令人绝望的代码，突然感到一种前所未有的空虚。 我已经很久没有亲自动手写代码了。 我也已经很久，没有真正拥有过那段代码了。 在这个与神对话的时代，我选择了沉默，也选择了失语。

JavaScript Async Patterns

从回调到 Promise，再到 async/await：异步之河的摆渡人 我初识 JavaScript 时，它像一条湍急而混乱的河。那时我们用回调函数过河，层层嵌套，像在河心垒石。一个接一个的函数压下来，代码缩进越来越深，直到变成所谓的“回调地狱”——维护代码的人，像困在迷宫里的守夜人，再也找不到出口。 后来，Promise 出现了。它像一座桥，横跨在异步的河流之上。 “.then()” 像桥上的灯，一步步照亮前行的路； “.catch()” 则是桥下的网，哪怕失足，也不会坠入深渊。我们终于可以把“成功”与“失败”清晰地分开，不再让错误在层层回调中悄然蒸发。 可桥再稳，走的人多了，依旧会觉得疲惫。于是 ES2017 带来了"async/await"，像一艘平稳的渡轮。你站在甲板上，代码看起来像同步的那样优雅，却依旧拥有异步的力量。 “await” 是短暂的停顿，像呼吸之间的留白； “async” 则是航向，宣告这个函数终将驶向远方。 但河流总有暗礁。忘记 “await”，就像跳上一艘无人掌舵的小船，不知何时就会撞上礁石；滥用"try/catch"，则可能把错误吞进漆黑的河水，再也浮不上来；而在循环里不加思索地使用 “await”，又会把本该并行的溪流，硬生生堵成一条窄渠。 异步的进化，不只是语法的变迁，更是思维方式的成熟。从混乱到秩序，从绕行到直抵，我们学会了在不确定中寻找确定，在等待中保持清醒。 JavaScript 的异步之旅，从未停止流动。而我们，也只是这条河上的摆渡人——愿每一次"await"，都值得被温柔地 “resolve”。

Understanding Go Modules

Understanding Go Modules 我最初接触 Go 的时候，它像一座没有围墙的城。代码就那样散落在 “$GOPATH/src” 下面，像旧书店里堆得老高的纸卷——你知道它们有用，却总在找某本书时碰落一整摞。那时我们常说：“GOPATH 就是家。”可家的规矩太宽，宽到依赖飘在风里，今天能跑的程序，明天就可能因为一个第三方库的更新而崩塌。 后来，Go Modules 来了。 它不是一声惊雷，而像一场迟来的春雨。第一次在终端敲下 “go mod init”，屏幕上安静地吐出一行 “go.mod”，那一刻，我竟有些莫名的感动。这个文件不大，却像给漂泊的代码发了身份证：谁是你，你依赖谁，你要去往哪里的版本。不再盲从 “master” 分支的潮水，不再被不可控的更新淹没。 “v1.0.0”、 “v1.2.3”——语义化版本像灯塔，把黑夜里的船一盏盏引回港湾。 我开始学着理解它，而不只是使用它。 “go.sum” 不是累赘，是守护者。它默默记下每一个模块的哈希值，像守夜人核对每一个进出城门的旅人。你不常注意它，但它一直在那里，确保你拿到的，正是你以为的那个世界。 “replace” 是我调试时的小秘密，本地替换掉远程包，像把远方的山搬进后院，细细端详。 “exclude” 则是温柔的拒绝——有些版本，注定不该与你同行。 最动人的是 “minimal version selection”。Go 没有选择“最新”，而是选择“足够”。它不相信永远向上，只相信可重复、可依赖。这像极了成年人的爱情：不追最热烈，只求最安稳。 如今，我的项目整齐得像一座座小小的城邦。 “go.mod” 是宪法， “go.sum” 是历史， “vendor” 是粮仓。我再也不必在深夜因为一个未知的依赖错误而惊醒。代码终于可以安心地生长，像树一样，年轮清晰，根脉扎实。 Understanding Go Modules，或许不只是理解一个工具。 它让我明白：真正的自由，从来不是无拘无束，而是清楚地知道——边界在哪里，归宿在何方。
